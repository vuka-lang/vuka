# E0181: A generic component's type arguments can't be inferred

A generic component's tag infers its type arguments from its attributes,
as Go infers a call's: each attribute's value is unified with the type of
the field it sets, so `data={orders}` setting `Data TableData[T]` makes
`T` the orders' row type. Reported by the compiler when:

- no attribute gives a type parameter: the message names the ones left,
  the help names the first prop whose type would give it, and the
  suggestion is the tag with the type arguments it could infer written;
- two attributes give a type parameter different types (`a={1}`,
  `b="x"` for `A, B T`), reported at the second;
- the tag writes its type arguments, and an attribute doesn't fit them but
  would give one of them another type, reported at the attribute;
- the inferred type arguments don't satisfy the type parameters'
  constraints.

A slot's content, `nil` and a left-out field give nothing.

`components.Grid` takes its rows and a format, and only the format
gives `V`:

```go
type Grid[T, V any] struct {
	Rows   []T
	Format func(T) V
}
```

## Wrong

```html
<components.Grid rows={Orders} />
```

## Right

```html
<components.Grid rows={Orders} format={orderTotal} />
```

or, with the type arguments written:

```html
<components.Grid[entities.Order, int] rows={Orders} />
```
