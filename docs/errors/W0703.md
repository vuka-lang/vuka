# W0703: A layout reading the request

A folder's layout stays while the visitor moves between the pages below
it: its `Load` doesn't run again, and its sidebar keeps its scroll, its
menus their state. That holds for a layout reading only its path
parameters, which can't change under it. One whose methods — or the
functions of its package they call — read more of the request,
`web.Request(ctx)`, an `*http.Request`, its URL or query, could show
something stale, so it loads and renders again on every navigation, as
`vuka` registers it (`web.ReloadLayout`). It works; it is only slower, and
what it renders doesn't stay.

The usual reason is a menu marking the current page. Mark it in the
browser instead, with `ui.Link`'s `active`: the runtime follows the
address on every navigation.

## Wrong

```html
// pages/_layout.vuka.html
type Layout struct {
	Children ui.Node
	path     string
}

func (l *Layout) Load(ctx context.Context) error {
	l.path = web.Request(ctx).URL.Path
	return nil
}
<nav>
  if strings.HasPrefix(path, "/orders") {
    <a href="/orders" class="on">Orders</a>
  } else {
    <a href="/orders">Orders</a>
  }
</nav>
<main>{Children}</main>
```

## Right

```html
// pages/_layout.vuka.html
type Layout struct {
	Children ui.Node
}
<nav>
  <ui.Link href="/orders" active="prefix" activeClass="on">Orders</ui.Link>
</nav>
<main>{Children}</main>
```

A layout that does need the request (a banner keyed by a query parameter)
may keep reading it; the warning says what it costs. See [layouts that
stay](/web/folder-routes#layouts-that-stay).
