# W0801: A GraphQL field querying once per parent

A field method resolves once for each object it is a field of. On a type a
list reaches — `users { orders { … } } ` — a method that queries the
database itself runs one query per user: an N+1, a hundred queries for a
page of a hundred users. `vuka vet` warns about a field method of such a
type calling the orm without taking a loader.

A loader gathers the keys of every field asking for them and loads them in
one call: one query per level of the query, however long the list.

## Wrong

```vuka
// Orders queries the database for each user.
func (u User) Orders(ctx context.Context) ([]Order, error) {
	return Order.Objects.Filter(Order.UserID.Eq(u.ID)).All(ctx)
}
```

## Right

```vuka
@graphql.Loader
func OrdersByUser(ctx context.Context, userIDs []int64) (map[int64][]Order, error) {
	rows := Order.Objects.Filter(Order.UserID.In(userIDs...)).All(ctx)?
	out := map[int64][]Order{}
	for _, o := range rows {
		out[o.UserID] = append(out[o.UserID], o)
	}
	return out, nil
}

func (u User) Orders(ctx context.Context, orders OrdersByUser) ([]Order, error) {
	return orders.Load(ctx, u.ID)
}
```

A field holding an orm relation (`orm.FK`, `orm.M2M`) needs neither: it
loads through one already. See [Loaders](/web/graphql#loaders).
