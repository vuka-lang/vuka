# E0183: A field setting given by its tag and by an attribute

A form field's label, hint, placeholder, control and rules come from its
tags (`label:"…"`, `validate:"max=100"`) or from its attributes
(`@ui.Spec{…}`, `@orm.Char{Max: 100}`). Both keep working, but one setting
has one source: a field whose tag and attribute both set it — whichever
would win — is an error at the attribute.

## Wrong

```vuka
type Product struct {
    orm.Base
    Name string `label:"Name" validate:"max=60"` @orm.Char{Max: 100}
}
```

## Right

```vuka
type Product struct {
    orm.Base
    Name string `label:"Name"` @orm.Char{Max: 100} @ui.Spec{Max: 60}
}
```

A `Spec` may tighten the model's limits; a tag beside the model's
attribute would give the field two of them. The same holds between a
`@ui.Spec{…}` member and one of the [deprecated single
attributes](/ui/forms#field-singles) setting the same thing on one field —
`@ui.Spec{Max: 20}` and `@ui.Max(10)` — and between two `Spec`s on one
field: keep one of them.

```vuka
type Product struct {
    Code string @ui.Spec{Placeholder: "e.g. A-1"}   // not also @ui.Placeholder("…")
}
```
