# W0108: A markup call fits both with and without the render's ctx

A call in markup whose overloads include one taking a `context.Context`
first and one that doesn't can compile two ways: as written, and with the
render's `ctx` passed for it (see
[The Render's Context](/ui/templates#implicit-ctx)). The call as written
wins — `Items()` is the `Items` taking nothing — but nothing at the call
says so. Adding the zero-argument overload later moves every such call to
it with no change to the template, and removing it moves them back to the
one taking the request's context, with its identity and data access.

The warning names both calls. Write which one you mean: `Items(ctx)` for
the overload taking the ctx, `Items(/*vuka:noctx*/)` for the one without.
The marker, first between the parentheses, says the call takes no implicit
ctx; with it, a call that compiles only with the ctx is
[E0162](/errors/E0162). The editor offers both rewrites as quick fixes.
Reported by the compiler: `vuka vet`, `vuka build` and the editor show it.
A call with one fit — only `Items(ctx)` declared, or only `Items()` — is
not reported.

## Wrong

```html
<script lang="go">
package pages

import "context"

type Index struct{}

func (p Index) Items() []string { return everyItem() }

func (p Index) Items(ctx context.Context) []string { return itemsFor(ctx) }
</script>

<p>{len(Items())} items</p>
```

## Right

```html
<p>{len(Items(ctx))} items</p>                <!-- the request's items -->
<p>{len(Items(/*vuka:noctx*/))} items</p>     <!-- every item -->
```
