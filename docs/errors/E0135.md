# E0135: A ?= attribute that can't be left out by its value

`name?={v}` writes the attribute only when `v` isn't its type's zero
value: `<input id?={ID} placeholder?={Hint} />` leaves out `id` when `ID`
is `""`, and a component's prop written that way isn't set, so the prop
keeps its default. It takes an expression, on an attribute the element
writes or a prop of a component.

It is an error where there is nothing to leave out by zeroness:

- on a bool, which a plain `disabled={Busy}` already writes bare when true
  and leaves out when false;
- on a state, whose value changes in the browser, while `?=` is decided
  when the server renders;
- on a quoted value, an event handler, or what isn't an attribute of the
  element: `key`, `let`, `model`, `innerHTML`, `bind:`, `class:` and
  `style:`.

## Wrong

```html
<script lang="go">
package pages

type Search struct {
	ID   string
	Busy bool
}
</script>

<input id?="search" disabled?={Busy} />
```

## Right

```html
<script lang="go">
package pages

type Search struct {
	ID   string
	Busy bool
}
</script>

<input id?={ID} disabled={Busy} />
```
