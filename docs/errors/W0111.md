# W0111: A bare ? on a call into another package

A bare `?` passes the error on as the callee returned it. For a call into
another package that error says what failed there — `strconv.Atoi: parsing
"x": invalid syntax` — but not what this function was doing; several calls
deep, the message no longer says which request or record it was about.
`?("…")` adds that, as `fmt.Errorf("…: %w", err)` does, and `errors.Is` and
`errors.As` still see the error inside.

The check is off by default, like the `wrapcheck` linter it follows; a
module turns it on in `vuka.toml`:

```toml
[vet]
wrap_errors = true
```

Then `vuka vet` reports each bare `?` on a call into another package. A call
into the same package, and a `?` with context, are not reported.

## Wrong

```vuka
func load(id string) (User, error) {
	n := strconv.Atoi(id)?
	return find(n)
}
```

## Right

```vuka
func load(id string) (User, error) {
	n := strconv.Atoi(id)?("parsing user id %q", id)
	return find(n)
}
```
