# W0314: A form field set by a single attribute

A form field's label, hint, placeholder, control and rules are its tags —
`label:`, `help:`, `placeholder:`, `input:`, `autocomplete:`, `validate:`,
`msg:` — or, where a tag can't go (a `ui.Meta` member) or a model's field
describes its forms, the members of one `@ui.Spec{…}`. The single
attributes `@ui.Label`, `@ui.Help`, `@ui.Placeholder`, `@ui.Widget`,
`@ui.Autocomplete`, `@ui.Required`, `@ui.Email`, `@ui.Min`, `@ui.Max`,
`@ui.Pattern`, `@ui.OneOf` and `@ui.Msg` are an earlier third spelling of
the same settings. They still work; the compiler notes each use with what
to write instead, and `vuka fix attributes` rewrites them.

Most become a tag. A few become a `Spec` member, because no tag says the
same: `@ui.OneOf`'s values are the field's options (`Choices`), which a
`validate:"oneof=…"` rule isn't; `@ui.Pattern` is `Pattern`; a
`@ui.Required("…")` on a number is `Required`, since `validate:"required"`
also refuses 0. On a `ui.Meta` member every setting is the `Spec`'s.

## Wrong

```vuka
type Signup struct {
	Email string @ui.Email @ui.Label("Work email")
	Plan  string @ui.OneOf("free", "pro")
	Terms bool   @ui.Required("Accept the terms to continue")
}
```

## Right

```vuka
type Signup struct {
	Email string `label:"Work email" validate:"email"`
	Plan  string @ui.Spec{Choices: []string{"free", "pro"}}
	Terms bool   `validate:"required" msg:"required=Accept the terms to continue"`
}
```

A live page's fields keep their own attributes, `@validate.Required`,
`@validate.Max(50)` and the rest: they are the one spelling there.
