# E0160: A call in markup returns values markup can't take

Markup takes one value wherever it reads an expression: a `{…}` hole, an
attribute, a component's prop, a `for`'s range, an `if`'s or a `switch`'s
condition. A call there returning `(T, error)` is unwrapped: it is its `T`,
and an error fails the render as a `Load` or `Mount` error does (the page's
status from a `*web.Error`, else 500; the full error in the log; its text in
the browser only in development). Nothing else is:

- a call returning two values whose second isn't an `error`, such as
  `(User, bool)`;
- a call returning three values or more, such as `([]User, int, error)`;
- a call returning only an `error`, shown as a hole's or an attribute's
  value.

Call a method that returns the one value markup shows, or load the data in
a layout's or a guard's `Load`, or a live page's `@ui.Mount` hook, into a
field and show the field. A template's statements are Go's and take every
result: `user, ok := Store.Find(id)`.

A call in markup runs on every render, a live page's re-renders included:
each event, each patch. A query belongs in `Load` or `@ui.Mount`, run once,
its result in a field the markup reads.

## Wrong

```html
<script lang="go">
package pages

import "example.com/app/store"

type Users struct {
	Store *store.Store // Page(n int) ([]store.User, int, error)
}
</script>

<ul>
  for _, u := range Store.Page(1) {
    <li>{u.Name}</li>
  }
</ul>
```

## Right

```html
<script lang="go">
package pages

import (
	"context"

	"github.com/vuka-lang/ui/v2"
	"example.com/app/store"
)

type Users struct {
	ui.Live
	Store *store.Store
	users []store.User
	total int
}

@ui.Mount
func (p *Users) mount(ctx context.Context) error {
	var err error
	p.users, p.total, err = p.Store.Page(1)
	return err
}
</script>

<ul>
  for _, u := range users {
    <li>{u.Name}</li>
  }
</ul>
<p>{total} users</p>
```
