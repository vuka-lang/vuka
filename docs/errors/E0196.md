# E0196: A quoted value that is none of its prop type's constants

A quoted value on a prop whose type is a defined string type, or a number
on one of a defined integer type, is one of the constants the type's
package declares of that type. The compiler checks it against the
constants' values — the design vocabulary, `"outline"` and `"sm"` — never
their Go names, so a typo fails the build instead of rendering the wrong
style.

A type that declares no exported constants takes any value, and so does
one whose doc comment has a `//vuka:open` line: a type with a few presets
that takes other values too. A hole is never checked:
`variant={design.ButtonVariant(name)}` passes a value only known when the
page renders.

## Wrong

```html
<script lang="go">
package pages

import "example.com/app/design"

// design declares ButtonOutline ButtonVariant = "outline".
type Settings struct{}
</script>

<design.Button variant="outlien">Cancel</design.Button>
<design.Button variant="ButtonOutline">Cancel</design.Button>
```

## Right

```html
<script lang="go">
package pages

import "example.com/app/design"

type Settings struct{}
</script>

<design.Button variant="outline">Cancel</design.Button>
```

A type whose constants are presets of an open set says so in its doc
comment:

```go
// Accent is a colour: a preset or any CSS colour.
//
//vuka:open
type Accent string

const AccentBrand Accent = "brand"
```
