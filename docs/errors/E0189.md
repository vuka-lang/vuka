# E0189: A ui.Spec the compiler can tell is wrong

`@ui.Spec{…}` gives a form field's details in one attribute. Go's
type-check reports a member it hasn't; the compiler reports what is wrong
in the members it has:

- a `Msg` key that names no rule (`"uniq"`, with the rule it most likely
  meant); the rules are `required`, `min`, `max`, `len`, `pattern`,
  `oneof`, `choice`, `email`, `unique`, `number`, `whole`, `format`,
  `digits` and `file`;
- `Required: ""`: `Required` is the message of a required field;
- `Required` beside `Optional`: a field is one or the other;
- a `Max` above, or a `Min` below, the field's model's (`@orm.Char{Max:
  100}`): a form may tighten a field's limits, never loosen them;
- a choice the model's `Choices` haven't: a form may narrow them, not add
  to them.

## Wrong

```vuka
type Product struct {
    orm.Base
    Name string @orm.Char{Max: 100} @ui.Spec{Max: 120, Msg: ui.Msgs{"uniq": "Taken"}}
}
```

## Right

```vuka
type Product struct {
    orm.Base
    Name string @orm.Char{Max: 100, Unique: true} @ui.Spec{Max: 60, Msg: ui.Msgs{"unique": "Taken"}}
}
```

On a form type's `ui.Meta` member, the limits it answers to are those of
T's field, its `@orm` and `@ui` attributes both.
