# W0601: A component uses a design token no stylesheet defines

A vendored component — one of the components directory of `[ui]`, from
`vuka ui add` — is drawn with design tokens: CSS variables its classes name
through Tailwind utilities (`bg-background`, `ring-ring/50`), `var(--name)`
or `bg-(--name)`. A token none of the build's stylesheets declares — the one
holding the tokens, Tailwind's, and the local files they import — makes
nothing: the element renders unstyled, without an error. It happens when a
token is deleted from the block `vuka ui init` wrote, a class is misspelt
in an edit, or a library's component uses a colour its theme lacks.

`vuka vet` names the component, the token, the stylesheet that was expected
to define it — the design tokens', or the library's theme
(`styles/<library>.css`) for a token of the library's own — and the nearest
token that is defined. Tailwind's own colours and variables, and a custom
property the component sets itself, are defined.

## Wrong

```vuka
<span class="inline-flex rounded-md bg-rnig px-2 text-primary-foreground">{Children}</span>
```

## Right

```vuka
<span class="inline-flex rounded-md bg-ring px-2 text-primary-foreground">{Children}</span>
```

Or define the token, in the block of design tokens:

```css
@theme inline {
  --color-rnig: var(--rnig);
}
```

See [Undefined Tokens](/ui/vendored#undefined-tokens).
