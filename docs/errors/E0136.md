# E0136: A prop's default that can't be

A prop declares its default in its `vuka` tag, and a tag that leaves the
prop out gets it:

```go
type Button struct {
	Type string `vuka:"default=button"`
	Tone Tone   `vuka:"default=ToneNeutral"`
}
```

The value is read as the field's type: a string's text, a number, `true`
or `false`, or the name of a constant of the field's package. A tag that
sets the prop, even to its zero value (`type=""`), sets what it says.

The default is an error, reported at the field, when it is none of those:
a number that doesn't parse or overflows the type, a name no constant of
the package has, a value of a type with declared constants that is none of
them (as a quoted value on the tag would be, E0196), a default on a field
that isn't a string, number or bool, a default beside `required`, which
can never be missing once it has one, or an exported prop's default naming
an unexported constant, which a tag in another package can't read. Another
package's constant is written as a reference to it, so a change of its value
reaches every tag.

## Wrong

```go
type Tone string

const (
	ToneNeutral Tone = "neutral"
	ToneDanger  Tone = "danger"
)

type Badge struct {
	Tone  Tone   `vuka:"default=ToneNeutrl"`
	Size  int    `vuka:"default=large"`
	Label string `vuka:"required,default=New"`
}
```

## Right

```go
type Tone string

const (
	ToneNeutral Tone = "neutral"
	ToneDanger  Tone = "danger"
)

type Badge struct {
	Tone  Tone   `vuka:"default=ToneNeutral"`
	Size  int    `vuka:"default=2"`
	Label string `vuka:"default=New"`
}
```
