# W0405: An environment read whose key the compiler can't read

When a config server changes a variable the program reads only while it
starts (a listen address, a database URL read once to open a pool), the
running program can't take the change. The compiler finds those variables
by reading every `web.Env`, `web.MustEnv` and `web.Require` call, and
records them so the config client can say that a change to one takes effect
on restart.

It can only read a key written as a string constant: a literal, a constant
of the module, or a concatenation of those. A call whose key is a variable,
a parameter or the result of a call isn't classified, so a change to the
variable it reads is applied but never reported as needing a restart.

`vuka vet` warns with the number of such reads and where the first ones are.
Calls in other modules, dependencies included, aren't read at all.

## Wrong

```go
func setting(name string) string {
	return web.Env[string](name)
}

var dsn = setting("DATABASE_URL")
```

The database URL is read once, at start, and the compiler sees only
`web.Env(name)`.

## Right

```go
const databaseURL = "DATABASE_URL"

var dsn = web.Env[string](databaseURL)
```

Or, for a value that does change while the program runs, keep the handle:
`web.Hot[string]("DATABASE_URL")` or `web.OnEnvChange`, whose keys the
compiler treats as handled by the program.

See [Reading Values](/web/configuration#reading).
