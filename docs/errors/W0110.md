# W0110: A ? on the right of && or ||

`a && f()?` calls `f` only when `a` is true, as Go's `&&` does, so whether
the function can return there depends on the left side: the `?` is a way
out that some calls take and others don't, hidden in a condition.

The code compiles as written: with no `else`, the `if` nests (`if a {
allowed, err := f(); …; if allowed { … } }`); otherwise a variable holds the
condition. `vuka vet` reports it; a statement of its own makes the call, and
its return, unconditional or plainly conditional.

## Wrong

```vuka
func edit(u *User, p *Post) error {
	if u != nil && canEdit(u, p)? {
		p.Locked = false
	}
	return nil
}
```

## Right

```vuka
func edit(u *User, p *Post) error {
	if u == nil {
		return nil
	}
	if canEdit(u, p)? {
		p.Locked = false
	}
	return nil
}
```
