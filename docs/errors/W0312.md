# W0312: A form field's control leaves out a constraint attribute

`vukavet -forms.attrs` (off by default) notes, for each field of a struct
form, the constraint attributes its control is rendered without, and why.
A form is `novalidate` — the server's messages are the ones a visitor reads —
and a control carries only the attributes the browser decides exactly as
the server does:

| Attribute | Written | Left out because |
|---|---|---|
| `minlength`, `maxlength` | on a field of digits (`input:"numeric"`) | the browser counts UTF-16 units and Go counts characters: an emoji is two to one and one to the other |
| `min`, `max` | on a `type="number"` input | — |
| `required` | with `ui.Config{RequiredAttr: true}` | the browser takes spaces for a value, where the binder trims them |
| `pattern` | never | the browser's regular expressions aren't Go's |

The rule is still checked: on every change on a live page, and on every
submit. Nothing needs changing; turn the note off by leaving out the flag.

The note marks what isn't written; there is nothing wrong to fix but a
field whose characters are only digits, which can say so and get its
attributes.

## Wrong

```go
type Signup struct {
    ui.FormState
    Postcode string `validate:"required,len=5"` // W0312: no minlength or maxlength
}
```

## Right

```go
type Signup struct {
    ui.FormState
    Postcode string `input:"numeric" validate:"required,len=5"` // minlength="5" maxlength="5", a numeric keyboard
}
```
