# Two ways to write Vuka

A Vuka app can be written as `.vuka` files or as plain Go. Both call the
same libraries — [web](/web/), [ui](/ui/) and the [ORM](/orm/) — and run
the same code: a page, a route or a model behaves the same whichever way it
was written.

The switch at the top of the sidebar picks which one the code samples show.
The choice is remembered in this browser, and `?style=go` or `?style=vuka`
in a link opens a page with that choice.

## Vuka

A `.vuka` file is Go with a few additions: decorators that register routes,
pages and services, JSX for markup, attributes on fields, `Result`, `?` and
`match`. The `vuka` command turns each file into Go as it builds.

```vuka
@web.Live("/counter")
type Counter struct {
	ui.Live
	n int
}

func (c *Counter) Inc() { c.n++ }

func (c *Counter) Render() ui.Node {
	return <div><output>{c.n}</output><button onClick={c.Inc}>+</button></div>
}
```

## Go

The same page in plain Go: registrations are calls, markup is a
`ui.Template` with numbered holes, field attributes are values passed to a
`Schema` method. `go build` and `go run .` build it; the `vuka` command is
not needed.

```go
type Counter struct {
	ui.Live
	n int
}

func NewCounter() *Counter { return &Counter{} }

func (c *Counter) Inc() { c.n++ }

var counter = ui.Template(`<div><output>{{0}}</output><button onClick="{{1}}">+</button></div>`)

func (c *Counter) Render() ui.Node { return counter.Render(c.n, c.Inc) }

func init() {
	web.Routes.Live("/counter", NewCounter)
}
```

| `.vuka` | Go |
|---|---|
| `@web.Get("/pets/{id}")` on `ShowPet` | `web.Routes.Get("/pets/{id}", ShowPet, web.Params("id", "store"))`, or `app.Get(…)` in `main` |
| `@web.Live("/x")` on a type | `web.Routes.Live("/x", NewX)` |
| `@web.Service` on a type | `web.Routes.Service(NewX)` |
| `@ui.Island(opts…)` beside a route | the route's option: `ui.Island(opts…)` |
| JSX: `<li>{x}</li>` | `ui.Template("<li>{{0}}</li>").Render(x)`; `ui.Each`, `ui.If` for lists and conditions |
| `Title string @orm.Char{Max: 200}` | `s.Field(&p.Title, orm.Char{Max: 200})` in `func (p *Post) Schema(s *orm.Schema)` |
| `Post.Objects`, `Post.Title` | `orm.For[Post]()`, `PostFields.Title` (generated by `ormgen`) |
| `@orm.Transaction` | `orm.Transaction(ctx, func(ctx context.Context) error { … })` |
| `Result[T]`, `?` | `(T, error)` and `if err != nil` — `vuka.Result[T]` works too |

## The same runtime

`.vuka` adds syntax and nothing else. What a decorator, a JSX element or an
attribute does is a call on the libraries' public API, and the transpiler
writes the Go a person would write against it. Nothing in a `.vuka` file
reaches a hidden part of the runtime, so anything a `.vuka` app does, a Go
app can do with the same calls.

What only makes things faster stays separate: the ORM's row scanners and
typed fields, live render tracking and island types are generated files
(`go generate`) that both kinds of app use, and both work without them.

## Eject

`vuka eject` writes the Go for `.vuka` files beside them, and `vuka eject
-rm ./...` deletes the `.vuka` files and keeps their Go as the source: a
plain Go module that builds with `go build` and behaves as before. See
[eject](/tools/cli#eject).

## Mixing both

`.vuka` and `.go` files live side by side in one package and call each
other. A team can write models in Go and pages in `.vuka`, keep a Go
package of routes next to `.vuka` ones, or move a file from one form to the
other at any time: the app registers the same routes either way.

Checks work for both. `vuka build` reports errors with codes at the `.vuka`
line; a Go app gets the same checks from [`vukavet`](/tools/vukavet), run by
`go vet`.

## Writing these docs

Pages show a sample for each preference in containers:

````md
::: vuka
```vuka
@web.Get("/pets")
func ListPets(store *PetStore) Result[[]Pet] { return store.All() }
```
:::

::: go
```go
func ListPets(store *PetStore) ([]Pet, error) { return store.All() }

func init() { web.Routes.Get("/pets", ListPets) }
```
:::
````

Inline text can follow it too, with `<span class="vuka-only">…</span>` and
`<span class="go-only">…</span>`. A sample without a container shows for
both.
